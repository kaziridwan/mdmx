# mdmx 0.7.0

The first npm release of mdmx (`@mdmx/*`, MIT). 0.6.0 was prepared but never
published; everything it built ships here, under four 0.7 themes: the source
pane edits both ways, components are edited where the caret is, blocks
insert usable, and the dashboard makes room.

## The source pane edits both ways

- The right-hand pane is a **CodeMirror 6 editor** over the canonical MDMX.
  What you type applies to the canvas live — 300 ms after the last
  keystroke, or ⌘/Ctrl-⏎ now — through the same parse path a file load
  uses, so the canvas shows exactly what a load of that text would show
  (an unknown component becomes a raw block).
- A syntax error keeps the canvas on the last applied version and says so
  ("Syntax error, line N"). Validation diagnostics (MDMX001–010) are lint
  markers with their codes — informational, never a blocker.
- While the pane is focused, your text is authoritative; on blur it snaps
  to the canonical form once. Canvas edits keep flowing into the text, and
  the block under the pane's cursor is outlined on the canvas. "Edit
  source" on any block jumps the pane to its first line.

## Component editing

- The **prop panel follows the caret** into nested blocks, with a
  breadcrumb (`Card › Tabs › Tab`); a crumb selects that ancestor. Editing
  a prop keeps the block selected.
- Real controls for every kind: **`list`** (rows with add / remove /
  reorder, nested for lists of lists), **`object`** (a control per
  field), `link` (with a placeholder), `color`, `date`. Effective defaults
  show muted with a per-field reset; **`showIf`** hides props that don't
  apply.
- **Block actions** on the contextual block — move up/down, duplicate, edit
  source, delete — from a toolbar anchored to the block and from ⌘⇧↑/↓,
  ⌘⇧D, ⌘⇧⌫.
- A live render that throws recovers as soon as the offending prop changes.

## Registry v3

- **`preview`** in `defineMDMX` is extracted and seeds every insert (palette,
  slash menu, rail drop): its props over the `default`s, plus `children`
  as the first paragraph's text. Keys must be declared props.
- **`showIf: { prop, eq? }`** on a prop hides its control unless the
  governing prop equals `eq` (or is truthy). Panel-only; content is never
  rewritten.
- `link` controls take a `placeholder`.
- v1 and v2 registries read unchanged; run `mdmx generate` once.

## Blocks that insert usable

- All 39 demo blocks revisited: every required prop has a component
  default that the registry mirrors, arrays are real `list` props
  (`Kbd.keys`, `Table.columns`/`rows`, `Tabs.tabs`, `LogoCloud.names`),
  tooltips and hover cards preview on hover, and the cheap variant gaps are
  closed (`Badge.href`, `Item.size`/`href`, `Separator.orientation`,
  `Tabs.orientation`/`defaultTab`, `Tooltip.align`/`sideOffset`,
  `HoverCard.side`/`align`, `TwoColumn.ratio`, `columns` on PricingTable
  and StatsBand). Canvas and page agree on every measured property.

## Dashboard

- The left navigation collapses from the navbar (⌘\ / Ctrl-\), persisted
  per browser, so the entry editor stops being four columns wide.

## From 0.6 (never published)

- **The canvas is the page**: the editor puts your content class on its
  canvas root (`mdmx-page` by convention, `contentClassName` to change it),
  so your site's typography, colors, and component styles apply while
  editing. `fit` is the default preview; mobile/tablet/desktop are framed
  device previews; the rail and the sidebar collapse from the toolbar.
- **Components are live**: buttons, inputs, tabs, and accordions work inside
  the editor; clicking anything else selects the block; links never
  navigate (⌘-click opens a tab). Override per component with
  `render: { interactive: true | false }`.
- `@mdmx/editor` ships its chrome as `@mdmx/editor/styles.css`; the
  dashboard's stylesheet renders the same under Tailwind's preflight,
  another reset, or no global CSS.
- **shadcn, first-class**: `examples/demo-next` runs Next 16 (Turbopack),
  Tailwind v4, and the full shadcn set; 22 shadcn components are registered
  as blocks and the 17 marketing components are rebuilt on shadcn
  primitives. Studio components in a Tailwind app compile through your
  Tailwind build from a generated class manifest.
- MIT license; `pnpm pack:all` + `pnpm.overrides` for using mdmx from a
  checkout between releases (guide 08).

## Compatibility

- Peers stay `next >=15`, `react >=18`; the demo runs Next 16.3 / React 19.2.
- Registry schema v3 (`preview`, `showIf`, `link.placeholder`); v1/v2
  registries read unchanged. Run `mdmx generate` once.
- Content format unchanged: canonical MDMX round-trips byte-for-byte. Props
  stay static JSON — toggling a block in the canvas does not write the prop
  back (the `setProp` channel is the 0.8 candidate, ADR-060).
- `@mdmx/editor` adds CodeMirror 6 to the client-only editor chunk
  (about 256 KB gzipped on the editor route; never server-rendered).
